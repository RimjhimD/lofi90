Build a React + TypeScript + Tailwind "Bug Report Widget": a "Report a problem" button for staging sites and client review. The reporter points at the broken element, writes one line, and the report already carries everything a developer needs to reproduce it: page, a unique CSS selector, browser, screen, time, recent console errors, failed requests and the clicks that led there. No extra libraries. Put the DOM helpers (selector, readable names, user-agent parsing, console/fetch/click capture, Markdown) in a small `context.ts` next to the component.

Props (typed): onSubmit (report => Promise<string | { id } | void>; the returned id is shown as the reference, a throw or rejection shows the retry state), shortcut (default "Alt+Shift+B", "" turns it off), open + onOpenChange (start it from outside; false → true starts pick mode), onStateChange, collect ({ console = true, network = false, breadcrumbs = true }), fullUrl (default false: query values in the page URL are shown as "…"), contained (a ref to a positioned element that contains the widget: picking and all overlays stay inside it), labels (partial overrides for every visible and announced string, including severities and item names), accent (hex, default "#C6FF3D"), size ("sm" | "md" | "lg"), position ("bottom-right" | "bottom-left"), dim (0–80 %, default 45), showTrigger, disabled, previewState ("idle" | "picking" | "picked" | "filling" | "invalid" | "submitting" | "sent" | "failed" | "disabled", drawn still with sample data) and className. Also export reportToMarkdown(report, labels?).

Behaviour:
- The button (or the shortcut, matched on e.code so Alt/Option works on macOS) starts pick mode. The page dims; the element under the pointer gets an accent outline and a tag with a readable name like button "Apply coupon" (role from the tag or role attribute, name from aria-label, aria-labelledby, alt, the field's label or placeholder, or its text). Hovering snaps to the nearest interactive ancestor.
- While picking, pointerdown/mouseup/click/contextmenu on the page are stopped in the window capture phase, so the broken button never actually runs. Click picks; Esc cancels; Tab / Shift+Tab steps through focusable elements and Enter picks; S skips picking. Each step is announced. The highlight follows scroll and resize.
- After a pick, a small bar confirms it: Describe it, Pick again, Cancel.
- The dialog is a real modal (inline previews drop the dialog role): role="dialog", aria-modal, labelled title, focus trap, Esc closes (the draft is kept until sent). Fields: what happened (required), what you expected, severity radio chips, optional email (checked if filled). Errors use aria-invalid + aria-describedby and focus moves to the first bad field.
- Context is read when the dialog opens: page URL and title; selector (stable id, then data-testid/data-test/data-cy, then aria-label or role+name, then name; otherwise an nth-of-type path that stops at the nearest uniquely named ancestor; each try verified with querySelectorAll to match exactly one element; React useId ids are skipped); element label, text and box; viewport, screen, device pixel ratio, colour scheme; browser and OS in words plus the raw user agent; ISO time, local time and time zone; the last 20 console errors/warnings, uncaught errors and unhandled rejections; failed fetches (method, URL, status, time) and recent clicks and route changes.
- Capture is installed on mount and fully undone on unmount (only restored if nobody wrapped after us). The fetch wrapper is opt-in. Form fields never contribute their value: text is read from a clone with inputs, textareas, selects and contenteditables removed. Query-string values in request URLs, route crumbs and (unless fullUrl) the page URL are replaced with "…". Console lines are redacted: emails, JWTs, bearer tokens, key=value secrets (token, key, password, session…) and long random strings become placeholders. React useId and other generated ids (":r1:", "_R_…_", radix-/mui- prefixes, hashes, long letter+digit runs) are never used in selectors.
- An "Attached for the developer" disclosure lists every item with a preview and a checkbox; unticked items are left out of the report, the Markdown and the JSON.
- Send shows a spinner and aria-busy and locks the fields and the close button and Esc (no duplicate sends); success shows the reference id with Done; failure keeps everything and turns the button into Try again. "Copy as Markdown" writes a GitHub-issue-ready text (title, severity, what happened, expected, element, environment table, console block, failed requests, numbered steps); "Download JSON" saves the report.

Look: clean control-room style. Accent pill button in a corner with an icon, text colour chosen for contrast on the accent. Dim layer with the highlight cut out via a huge box-shadow, 2px accent outline, accent name tag above (or below near the top edge). Floating instruction bar at the top while picking, confirm bar at the bottom after picking. Dialog in var(--k-panel) with 1px var(--k-line) borders, fields in var(--k-panel-2), severity chips filled with the accent when chosen, errors in var(--k-err-text), focus rings in var(--k-acc-text), so it reads on light and dark stages. Highlight and spinner motion only with motion-safe. Works at 375px wide.
