Build a React + TypeScript + Tailwind "Wax Seal Button": a submit button for Pay / Place order / Send / Book that stamps a wax seal onto itself when pressed. Once sealed it cannot fire again, it sends one idempotency key with every try so the server can dedupe, it waits for the connection when offline, and it retries busy-server errors by itself. No extra libraries.

Props (typed): onSubmit(key) (does the real request; may return a Promise; send key as the Idempotency-Key), onSuccess(result, key), onError(error, key), onRetry({ attempt, delayMs, error, key }), onQueued(key), onDuplicate() (a press that was ignored), maxRetries (default 3), baseDelayMs (default 1000), resetAfterMs (optional: after success go back to idle with a fresh key), online (optional override of connection detection), labels (partial overrides for every visible and announced string: idle, sealing, queued, retrying with {s}, sent, error, sealingHint, queuedHint, retryingHint with {s} {n} {max}, sentHint, errorHint with {message}, errorFallback), disabled, pending (force the sending look), previewState ("idle" | "sealing" | "queued" | "retrying" | "sent" | "error" — render one state without running anything), accent (wax colour, default "#FF6B57"), size ("sm" | "md" | "lg"), glyph (1–2 characters pressed into the seal, default "✓"), className, and a ref exposing reset() and key(). Export a SealError type: Error with optional status, retryable and retryAfterMs.

Behaviour:
- Pressing makes ONE key per attempt-cycle with crypto.randomUUID (falling back to getRandomValues, then Math.random, formatted as a v4 UUID). Every retry reuses it. A new key only comes after reset(), or after resetAfterMs following a success.
- Single-flight: a ref lock is set synchronously on the first press, so five clicks in the same tick or a held-down Enter key still call onSubmit once. Key-repeat Enter/Space is also prevented. Ignored presses call onDuplicate.
- Offline at press time (navigator.onLine false, or the online prop false), or a TypeError from onSubmit while offline: state "queued", the seal goes grey and cold, label "Sealed · will send when you're back online". When the connection comes back (online event or the prop), it sends by itself with the same key. Read the connection with useSyncExternalStore so server and client render the same thing.
- Retryable failures: an error with retryable: true, a status of 408/429/500/502/503/504, or a TypeError while online. Retry up to maxRetries times with exponential backoff (baseDelayMs × 2^n), or exactly retryAfterMs when the error carries it. Show "Retrying in 3s…" with a live countdown and a warm pulsing glow; announce the plan once, not every second.
- Non-retryable failure or retries used up: state "error", the seal cracks and shakes, the status shows the error's message, and the button can be pressed again with the same key.
- Success: state "sent", a glint sweeps across the seal, label from labels.sent, and it stays sealed (aria-disabled) unless resetAfterMs is set.
- Status text in a role="status" region linked with aria-describedby; aria-busy while sending or waiting to retry. reset() and unmount drop any answer still on its way and clear all timers.

Look: the idle button is filled with the wax colour (text colour picked for contrast) with a dashed ring where the seal will land. On press the seal drops in from above, squishes flat and springs back (Web Animations, skipped with reduced motion), and the button turns to a paper-like panel colour. The seal is an SVG: a lumpy wax blob computed once at module load (rounded so server and client match), a radial gradient from a light mix of the accent to a dark mix (color-mix), an inner pressed ring, and the glyph debossed with a dark and a light offset copy. Grey for queued, cracked with dark lines for error, a white glint band clipped to the blob for sent. Control-room colours from --k-* CSS vars with dark fallbacks so it works on light and dark stages, visible focus ring in var(--k-acc-text), hover lift and pressed sink only while pressing would do something.
