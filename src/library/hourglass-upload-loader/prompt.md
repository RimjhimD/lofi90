Build a React + TypeScript + Tailwind "Hourglass Upload Loader": an upload indicator drawn as an SVG hourglass whose sand is the real progress. The top bulb holds the bytes still to send, the bottom pile holds the bytes sent, and a thin stream falls between them while data is moving. Underneath sit the file name, "4.2 MB of 12 MB", the measured speed and an honest time left. It is a pure display component: it never uploads anything itself, it shows what your upload code tells it and measures speed and time left on its own. No extra libraries.

Props (typed): loaded (bytes sent), total (file size in bytes; 0 or not finite means unknown), status ("idle" | "uploading" | "paused" | "offline" | "done" | "error"), fileName, onPause, onResume, onRetry, onCancel (each button only appears when its callback is given), errorMessage (shown instead of the default error text), disabled (turns the buttons off), labels (partial overrides for every visible and announced string: progressLabel with {file}, idle, uploading with {file}, indeterminate, paused, offline, done, error, sentOf with {sent} and {total}, sentOnly, percent with {pct}, speed, working, stalled, lessThan5, seconds and minutes with {n}, hours with {h} and {m}, clock with {t}, spoken versions of the time-left strings, valueText with {pct} and {eta}, pause, resume, retry, cancel), accent (sand colour, default "#FFB547"), etaStyle ("words" for "about 40s left", "clock" for "0:40 left"), size ("sm" | "md" | "lg"), previewState ({ status, progress?: 0..1 or null for unknown size, total?, speed? } — render one state frozen, measuring nothing) and className.

Behaviour:
- Sand levels are set by area, not height: the bulbs narrow toward the neck, so the curve is sampled once into a cumulative-area table and each level is solved from it. Half the bytes sent looks like half the sand moved.
- Sand surfaces move with CSS transforms (translateY inside a clipPath of each bulb) so every progress update eases over half a second. The stream is a dashed line animated with SVG animate.
- Speed is sampled every 500 ms on a steady clock (not on progress events), turned into bytes per second and smoothed with an exponential moving average (time constant about 2.5 s, weighted by the real gap between samples). Paused and offline time is never measured.
- Time left counts down in real time and leans toward the fresh estimate: quickly when it should drop, slowly and capped when it should rise, so it never counts up wildly. Until four samples exist it says "working it out…". Under 5 seconds it says "less than 5s left". It is hidden while paused or offline.
- No bytes for 3 seconds while uploading: "Nothing is moving. Waiting for the network…" in the warning colour, instead of a frozen number.
- A smaller loaded value than before (retry from zero, new file) resets the measurements.
- Paused: the hourglass tilts about 12°, the stream stops, Resume and Cancel show. Offline: it tips 90° onto its side with "Paused · no connection. It'll continue when you're back." Back to uploading: it springs upright.
- Done: one full turn with a slight overshoot, a check badge pops on in the sand colour, "Uploaded". Error: a crack is drawn across the top bulb, a short shake, the message in the error colour and a Retry button.
- Pause, Resume and Retry are one stable button whose label and action change with the state (offline keeps Pause, which stops the automatic carry-on), so keyboard focus never drops. If the buttons disappear while focused (done, cancelled), focus moves to the hourglass.
- Unknown total: the sand trickles in a loop (top falls, bottom rises, back again) and only bytes sent are shown.
- The hourglass is a role="progressbar" with aria-valuemin/max/now and aria-valuetext like "42%, about 40 seconds left" (no value numbers when the size is unknown). A separate visually hidden role="status" region announces state changes only, never every byte. Buttons are real buttons.
- prefers-reduced-motion is read with useSyncExternalStore (no hydration mismatch): no stream animation, no trickle loop, no tilting transitions, no shake.

Look: control-room card — var(--k-panel) background, 1px var(--k-line) border, rounded corners, soft var(--k-shadow). The glass is var(--k-panel-2) with a var(--k-text) outline and a faint white glint; the frame caps and posts use var(--k-mute). Sand, stream, check badge and the Resume/Retry buttons use accent, with button text picked for contrast. Numbers are monospaced and tabular. Offline text uses var(--k-warn-text), errors var(--k-err-text), done var(--k-acc-text). Buttons lift on hover, sink when pressed, dim when disabled and show a var(--k-acc-text) focus ring. Works at 375px wide.
