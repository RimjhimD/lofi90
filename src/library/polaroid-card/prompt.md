Build a React + TypeScript + Tailwind "Polaroid Card": an image card shaped like an instant photo that handles image loading honestly. It reserves the photo's space so nothing jumps, "develops" from a dark chemical tint while the image really loads, turns into an overexposed print with a Retry button when the image fails, and puts a yellow sticky note on itself when alt text is missing. No extra libraries, no font downloads.

Props (typed): src, alt, width, height, aspectRatio (wins over width/height; default 4/3), srcSet, sizes, loading ("lazy" | "eager", default "lazy"), caption (ReactNode), date (string), href (whole card is a link), onSelect ((selected: boolean) => void; whole card is a toggle button), selected, disabled, placeholderColor (default "#3C2A1E"), blurDataURL, slowAfterMs (default 4000), maxRetries (default 2), cacheBust (default true; turn off for signed URLs such as S3 or CloudFront, where an extra query param breaks the signature, and use onRetry to fetch a freshly signed URL), onRetry, onLoad ((img) => void), onError (({ src, attempt }) => void), labels (partial overrides for developing, slow, error, retry, gaveUp with an {n} placeholder, missingAlt, missingAltHint), altGuard ("dev" | "always" | "off", default "dev"), accent (tape and Retry colour, default "#C6FF3D"), size ("sm" | "md" | "lg" = 180 / 240 / 300px wide, never wider than the container), tilt (degrees, default -2), previewState ("developing" | "developed" | "slow" | "error" | "missing-alt" | "selected" | "disabled", renders one state without timers) and className. Nothing is hard-coded.

Behaviour:
- The photo window has CSS aspect-ratio from aspectRatio, or width / height, so space is reserved before any pixels arrive: zero layout shift. The image is a plain <img> with loading, decoding="async", width, height, srcSet and sizes passed through.
- Developing: a placeholder (placeholderColor, plus blurDataURL blurred if given) sits under a dark brown-to-teal gradient tint. One frame after mount the tint starts thinning slowly (linear, over about 1.5 × slowAfterMs). The image itself stays hidden and sepia-dark until it is ready.
- Ready means the load event fired and img.decode() settled. Only then does the tint fade out (about 1.4s), the image fades in and loses its sepia filter, and onLoad runs. If the image was already complete before React attached handlers (cache or hydration), an effect checks img.complete and naturalWidth and settles it the same way. Each request is keyed by src and attempt, so a new src or a retry starts fresh and a late result from an old request is ignored; onLoad and onError never fire twice for one request.
- Slow: the clock starts only once src is set and the image is actually requested: loading="eager", or the card has come within 200px of the viewport (IntersectionObserver), so lazy photos below the fold are never called slow. If still developing after slowAfterMs from then, the caption area says "Still developing… slow connection" in amber ink.
- Error: the photo window becomes an overexposed, near-white print with warm light leaks in two corners and a small broken-photo icon. The caption says "Couldn't load this photo" in red. A Retry button (accent colour, text colour picked for contrast) re-requests with a cache-busting ?retry=n on src and every srcSet entry, up to maxRetries times; after that it says "Gave up after {n} tries". With cacheBust false the same URL is re-requested. If onRetry is given, Retry calls it instead and the parent changes src. Retry unmounts when pressed, so focus moves to the card first (a plain figure gets tabIndex -1) and goes back to Retry if the photo fails again and focus is still on the card.
- Missing alt: alt undefined (not "") shows a tilted yellow sticky note "Missing alt text" with a hint, and warns once in the console. altGuard "dev" does this only when process.env.NODE_ENV is not "production"; alt="" is treated as decoration and never warned about.
- Actions: href makes the card one <a>; onSelect makes it one <button aria-pressed>. Retry is a sibling button positioned over the frame, never nested inside. When selected, a translucent strip of tape in the accent colour holds the top of the card. Hover and keyboard focus lift the card 6px and turn it by tilt degrees; pressing sinks it slightly. Disabled cards are faded, grey and do not lift. A plain card with neither is a <figure> with a <figcaption>.
- Slow and error messages are announced in a visually hidden role="status" region.
- Reduced motion (read with useSyncExternalStore, so no hydration mismatch): no slow drift, no pulse, just a quick 200ms fade.

Look: a real instant photo. Off-white #FBFAF6 frame with a 1px faint edge and a soft drop shadow, even borders on three sides and a thicker bottom holding the caption. The caption is in a handwriting font stack using system fonts only ("Segoe Print", "Bradley Hand", "Marker Felt", "Chalkboard SE", "Comic Sans MS", cursive), in blue-black pen ink #1F2A44, turned 1 degree. The date sits under it in grey pencil. The frame stays white on both dark and light stages; the focus ring uses var(--k-acc-text) with an offset so it reads on both.
