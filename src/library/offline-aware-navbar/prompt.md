Build a React + TypeScript + Tailwind "Offline-Aware Navbar": an app navbar that knows about the connection. When the internet drops, a calm strip slides down under it saying "You're offline · 2 changes waiting" and the connection icon changes; when it comes back the strip says "Back online · syncing 2 changes…", then "All changes saved ✓", and slides away. It ships with a small offline queue that holds the changes. No extra libraries.

Props (typed): brand (ReactNode), links ({ label, href, active?, disabled? }[]), onNavigate(link, event), right (slot), queue (an OfflineQueue; defaults to a shared one), ping (URL or function, optional heartbeat), pingInterval (default 30000), savedMs (default 2500), forceStatus ("online" | "offline" | "slow", for demos and tests), onStatusChange, stripPosition ("below" | "top"), labels (partial overrides for every visible and announced string, with {n} and {t} placeholders and separate one/many forms), accent (default "#C6FF3D"), warnColor (default "#FFB547"), size ("sm" | "md" | "lg"), previewState ("online" | "offline" | "offline-waiting" | "syncing" | "saved" | "failed" | "slow" | "menu-open") and className.

Queue and detection (offline.ts): `createOfflineQueue({ storageKey?, replay? })`, a shared `offlineQueue`, `queueAction(fn, label, { key?, payload? })` and `useOfflineQueue(queue?)` returning items, count, lastSyncedAt, statusOf(id) ("waiting" | "syncing" | "failed" | "saved"), add, retry(id?), remove and flush. It is an external store read with useSyncExternalStore. Also export a small `QueueStatusBadge` pill for list rows, with Retry on failed items.

Behaviour:
- Detection: navigator.onLine plus online/offline events (useSyncExternalStore, server snapshot "online"). With `ping`, a heartbeat runs every pingInterval; a URL gets a HEAD request with no-store and a 5s timeout, where any answer counts and only a network failure means offline. Failed checks retry with backoff from 2s, doubling up to pingInterval. "Slow" comes from navigator.connection (effectiveType 2g/slow-2g or rtt ≥ 1500) and is feature-detected. Clicking the connection icon checks again now.
- Queue: while online a new action runs straight away; while offline it waits. On reconnect the navbar calls queue.setOnline(true), which replays waiting items one at a time, in order. If an action throws while the connection is down it goes back to waiting and the replay stops. If it throws while online it is marked failed with its error and the others continue.
- Persistence is optional: only label, key and plain JSON payload are stored in localStorage, never functions. After a reload each item is rebuilt with `replay[key](payload)`. Items without a handler are dropped.
- Strip phases, in priority order: offline (with a count pill, or "Changes will save when you're back"), syncing (only during a reconnect or retry), failed ("1 change couldn't be saved" + Retry), saved (for savedMs; "Back online" when nothing was waiting), slow, hidden. While it slides away it keeps showing its last message.
- The strip slides open by animating grid-template-rows from 0fr to 1fr. It is inert while closed. Messages go to a separate sr-only role="status" aria-live="polite" span, so focus is never moved.
- The connection icon is a Wi-Fi glyph (dimmed and slashed offline, top arcs faded when slow) with a coloured dot. A tooltip on hover and focus reads "Online · last synced 2 min ago". The time is measured when the tooltip opens, not during render.
- Links are real anchors with aria-current="page". Under a 32rem container width (container query) they fold into a hamburger menu with aria-expanded/aria-controls. Opening it focuses the first link. Esc closes it and returns focus to the button, and so do a click outside or picking a link.
- With previewState nothing listens, nothing touches the queue, and links and buttons render as spans with sample counts, so it is safe inside a link card.

Look: control-room style. A var(--k-panel) bar with 1px var(--k-line) borders and a small initial mark in the accent colour, with text colour picked for contrast. Muted links get a 2px accent underline when active. The strip is tinted with color-mix: warnColor when offline, accent when syncing or saved, coral when failed. Its text is var(--k-text), so it reads on both dark and light stages. Hover, active and focus-visible states use a var(--k-acc-text) ring. Spinners and the slide are off with reduced motion.
